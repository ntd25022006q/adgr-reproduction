\section{Work done, part by part (each step with its difficulty)}
\begin{itemize}[leftmargin=*]
\item \textbf{Corpus:} crawled 1,934 medical articles (5 dead URLs, 4
recovered from alternates, disclosed); cleaned HTML keeping structure. Hard
part: transient 429 blocks required spaced retries over hours.
\item \textbf{Chunking:} one H2 section = one chunk $\rightarrow$ 15,837
chunks (91.9\% of paper; min 126, median 799, mean 1,079 chars). Hard part: no
author chunker code, so the H2 rule was inferred from the paper text and
validated by count.
\item \textbf{Graph:} Qwen2.5-14B temp 0 $\rightarrow$ 52,578 entities /
106,279 relations (paper: 49,274 / 106,666); 3.3 entities/chunk average (max 171
in a terminology-dense chunk). Hard part: 15,837 chunks through a 14B model
takes tens of GPU hours with occasional malformed outputs; per-chunk
checkpoints plus defensive parsing made it resumable.
\item \textbf{Retrieval:} 300 questions $\times$ 5 pipeline variants (full +
4 ablations, each disabling exactly one module per Sec.~5.8) + 2 LightRAG
baselines with rerank off per Sec.~5.2. Hard part: one GPU shared with vLLM +
ollama + reranker + someone else's training job (4.4GB) --- required a
per-stage VRAM budget, maxlen cuts, CPU keywords, and keyword memoization
(1 call/question instead of 5).
\item \textbf{Scoring:} Hit/MRR/nDCG (dual gold proxies); 4-part RAGAS by
official algorithms; AI judge on 4 dims $\times$ 5 independent runs; per-row
tokens and latency. Hard part: one dead API key mid-run poisoned 123 rows
before detection --- replaced by a quota guard that halts loudly instead of
ever silently marking failures as done.
\item \textbf{Quality control:} per-question checkpoints (any crash loses
$\le$1 row); self-checks after each stage (bad numbers halt loudly via
validation gates, 8 boundaries); every bug fixed with remote-verified
evidence (43 total).
\end{itemize}

\section{Deviations from the paper, each with its reason}
Every substitution below is fixed and disclosed; none is hidden in the numbers.
\begin{itemize}[leftmargin=*]
\item \textbf{Generator:} Qwen2.5-14B-Instruct-AWQ locally via vLLM, temp 0,
max 400 tokens (no access to the paper's commercial model; a strong open
model, temp 0 for determinism: identical inputs always yield identical answers).
\item \textbf{Embedding:} \texttt{embeddinggemma:300m} (768-dim) instead of a
commercial embedding (no API access).
\item \textbf{Reranker:} Qwen3-Reranker-0.6B instead of a commercial
cross-encoder (fits local VRAM, with per-row CPU fallback on mid-run OOM).
\item \textbf{Judge:} solar-pro4 instead of GPT-5.5 (no GPT-5.5 API access;
its strictness was measured via the original-prompt cross-check in Table 5).
\item \textbf{Gold labels:} the authors' manual gold $\rightarrow$ two proxies:
slug-gold (optimistic: correct = chunk from the same article) and single-gold
(pessimistic: correct = the single most similar chunk). Without hand-made
labels, paper numbers are never impersonated; both proxies are reported.
\item \textbf{Standalone:} the paper's 7 paid models $\rightarrow$ 7 free models,
zero overlap (reference points only, never ranked against the paper).
\item \textbf{Chunker:} H2 rule reverse-engineered (no code released; 91.9\%
match by count; measurable consequences: 3.3 entities/chunk and lower LCR).
\item \textbf{RAGAS:} reimplemented from the published formulas instead of the
official library (to share the solar judge and control cost; run on 295--300
samples with cross-checked formulas).
\item \textbf{One-step faithfulness} instead of the standard two-step (far
cheaper; impact measured on identical data: 0.41 vs 0.77 --- both reported,
see Figure 5).
\item \textbf{Own judging prompt} plus a cross-check with the original prompt
(Online Resource 1) on 3000 judgments (original prompt scores $\sim$0.08 lower
but keeps all rankings --- see Figure 7).
\end{itemize}

\section{Function of every entity in detail}
\begin{itemize}[leftmargin=*]
\item \textbf{Crawler:} 1,934 URLs $\rightarrow$ title, H2 tree, clean text,
source URL. Handles 404/timeout/429 by backoff retries + alternate sources;
gives up on 1 URL only after documented retries (disclosed, never faked).
\item \textbf{Cleaner:} drops ads/menus/recommendations/duplicates; keeps
titles, H2, URLs for traceability. Encoding audit: 0 mojibake across the
whole corpus (Vietnamese diacritics intact).
\item \textbf{Chunker:} H2-aligned sectioning with recursive split keeping
parent metadata (91.9\% author-chunker match).
\item \textbf{Extractor:} per chunk $\rightarrow$ entities (name, 10+1 type,
description) + relations (source, target, keywords, description) + source
chunk id, temp 0, delimiter format. 3.3 entities/chunk on average (max 171
in a terminology-dense chunk).
\item \textbf{Index:} normalized matrices (768-dim, chunks/entities/
relations), BM25 over entity names and descriptions, two-way
graph-to-chunk maps (960\,MB, 8 files).
\item \textbf{Keywords:} 3--6 short $K_l$ + 1-sentence $K_h$, lexical fallback
on LLM failure, memoized (1 call/question, not 5 --- 5x speedup).
\item \textbf{Anchors:} BM25 top-10 union dense top-10 outside BM25 filtered
by threshold, overlap bonus for entities found by both channels, top-15.
\item \textbf{Edges:} one-hop neighborhoods, edge filter, joint
anchor-plus-query score, quota $m$, cap $N_{max}$ (at most 50 edges total).
\item \textbf{Global/direct:} top-$n_g$ relations by broad keywords +
top-$n_s$ chunks by raw question (safety nets outside anchor neighborhoods).
\item \textbf{Merge:} rank keeping $\lfloor rn/2\rfloor$ per source,
round-robin interleave, dedup by id ($\sim$100-chunk pools).
\item \textbf{Reranker:} Qwen3-0.6B with GPU/CPU auto-pick and per-row
fallback (mid-run OOM degrades one row to CPU, never kills the run),
always exact-length scores (length contract verified).
\item \textbf{Generator:} vLLM Qwen2.5-14B-AWQ temp 0, 400 tokens max
(deterministic: same input always yields same answer).
\item \textbf{Judges:} Hit/MRR/nDCG (dual gold proxies), 4 RAGAS parts,
4 dims $\times$ 5 runs (cheap-first cost escalation, quota guard exits
loudly), token/latency timers.
\item \textbf{Merger:} 8 tables + 10 figures; any missing file lands in a
pending list, never skipped silently.
\end{itemize}

\subsection{Table 4 -- Grounded quality, the biggest gap, fully dissected}
Faithfulness 0.41 vs 0.89. Three measured layers, no guessing:
\textbf{Layer 1 (is the pipeline broken?):} our SHORT answers match paper
(0.89) -- pipeline intact, gap lives in long answers (more claims = more
chances to fail). \textbf{Layer 2 (is our scoring wrong?):} proper two-step
scoring on identical data reaches 0.77 -- $\sim$75\% of the gap is our
one-step judging shortcut. \textbf{Layer 3 (what remains?):} stricter judge
(solar vs GPT-5.5) plus noisier data (beyond reach: no GPT-5.5 access --
stated as a limit, not hand-waved). Relevancy 0.90, dim4 0.84 high. Precision
0.86 vs 0.97: precise but under-covering (recall 0.64 vs 0.94 -- compact
contexts have a price).

\section{Strengths, each with its number}
Paper: relevance control at the two most error-propagating stages (removing
anchors drops RAGAS most: 0.88$\rightarrow$0.72); compact contexts ($-23\%$
tokens) cutting retrieval-plus-generation latency (Tab.6:
9.85s$\rightarrow$8.18s); honest
ablations (one module off each, baselines not sabotaged); public resources
(corpus + code + prompts -- this reproduction exists because of them).
Ours: Table-2 config lock 13/13 (any single wrong number surfaces instantly
in comparison); gates blocking corrupt numbers (fired twice, both correct
catches); dual-proxy absolute agreement; every substitution disclosed with
measured effect (including ones flattering and unflattering alike); 43 fixes
with remote-verified evidence (log + file + assert, never blind).

%====================================================================
\section{Weaknesses and limits, each with its number}
Paper (Sec 6.3, their words, confirmed by our numbers): KG-quality dependence
(garbage in -- garbage out: our LCR 0.82 vs 0.91 shows it concretely);
fixed top-K budget (too much for easy questions -- our dense\_only already
suffices at 0.90 -- too little for hard ones needing more evidence).
Ours: (1) manual gold replaced by proxies -- single-gold favors dense by
definition (measured 0.90 vs full 0.79; disclosed, never presented as paper
numbers); (2) stricter judge, esp.\ long answers (short quartile 0.89 matches
paper exactly; longest quartile only 0.53); (3) different standalone models
(references only, never ranked against each other or paper); (4) noisier
extraction (LCR 0.82: chunker merges small sections, root cause identified to
the chunker, not hand-waved); (5) faithfulness gap decomposed above (75\%
protocol, 25\% strictness+noise).

\section{Proposed fixes (evidence + real cost each)}
(1) \textit{Question-adaptive pipeline:} dense\_only nears full (0.90 vs
0.79) $\rightarrow$ classify easy/hard up front, skip graph for easy,
$\sim$10$\times$ cheaper, expect $\ge$95\% quality (easy questions need no
graph by the same measurement). $\sim$4h GPU + $\sim$\$1 Solar (one new
ablation column on ready infra, KG untouched). (2) \textit{Rank-fusion instead
of rerank-override:} rerank drags single-gold Hit@1 $0.57\rightarrow0.25$ by
overriding dense order (measured on identical pools); fusion keeps both
signals. $\sim$3h, no new answers needed. (3) \textit{Sufficiency stopping}
instead of fixed top-K --- the paper's own future work: stop when
supported-claim count saturates across 3 consecutive chunks. $\sim$5h.
(4) \textit{Length-controlled generation:} short answers already match paper
(0.89); add a length cap and re-judge one arm. $\sim$4h. Total Phase-2:
$\sim$15h GPU + $\sim$\$5.

\section{Significance and conclusion}
Scientifically: independent confirmation that query-aware relevance control
(not blind graph expansion) drives ADGR's gains -- our ablations reproduce
the exact module-importance order on a different index with a different
judge, which is stronger evidence than rerunning the authors' code. Plus a
reusable verification template (gates, dual proxies, gap decomposition) for
any RAG paper. Practically: 52k-entity Vietnamese medical KG + runnable chain
+ rules from 43 real failures are permanent assets; each new idea now costs
marginal compute instead of a rebuild ($\sim$30h, $\sim$\$23 sunk once).
Conclusion: correct mechanisms, correct rankings, correct ablation
directions; absolute gaps quantified by cause. No mocking (every number ran
on real GPU with full logs: 84 stage logs), no cherry-picking (including the
5 rescued short answers and the 2 incoherent judge JSONs, all disclosed with
log line numbers), no invented numbers.
